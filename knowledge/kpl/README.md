# KPL 选手知识库

服务于剪辑助手的选手背景检索。收录范围是：2016年起，所有历史上在 KPL 联赛赛季正赛或 KPL 年度总决赛实际登场的选手。年度总决赛自 2024 年起单独分类，但纳入 KPL 正赛选手总名录；KPL 杯赛与其他官方职业赛事只作分开的生涯事实，不据此加入该名录。

当前范围与完整性见 [选手索引](INDEX.md)，也可按有来源支持的历史赛事队伍查看[战队分类索引](TEAMS.md)。战队分类只表示某条赛事事实记录中的对应队伍，不代表完整转会史或当前所属；未归类表示队伍证据待补。各历史队名对应的[官方微博信息源与沿革核验](../../docs/kpl-team-official-weibo.md)用于查找名单、转会和首发原帖。

选手数量分开核实：`appearance` / `debut` 事实中的已完成 KPL 联赛或年度总决赛实际登场用于实际登场人数；`roster_listing` 事实记录官方赛季大名单、年度总决赛大名单、单场名单或首发名单，用于去重统计列名人数，不能升级实际登场状态。年度总决赛名单使用 `annual_finals_roster`，与常规赛季 `season_roster` 分开统计。当前大名单覆盖仍不完整，不能把已收录人数当作历史总人数。

名单来源样本、两种计数口径与逐赛季核验流程见[大名单与实际登场人数研究记录](../../docs/kpl-roster-and-appearance-counting.md)。

2026 年度总决赛的 12 队官方名单来源、目前已核实名单及配图待补项见[2026 年度总决赛名单整理](../../docs/kpl-2026-annual-finals-rosters.md)。

用户提供的两份《KPL 十年编年史》文本均保留在 `sources/`。较早的完整版本用于抽取称呼与事迹候选，见[编年史候选导入索引](chronicle-import.md)和结构化记录 `data/chronicle_import.json`；2026-10-06 附件用作当前内容组织标准，但文件在个人高光表中途截断，因此不替换旧版或用于重算名录。所有编年史说法仍是待核线索，不进入已确认事实统计。`kb.py lookup` 会在正式档案旁返回对应的 `chronicle_source_leads`，未建档称呼也会返回“候选线索待核”提示。

截至 2026-10-04，库中有 75 条选手记录，65 条有已核 KPL 正赛登场证据、10 条待补；另有 14 位选手的 2026 年度总决赛大名单证据（按身份去重）。这不是历史总人数，也不代表名录或赛事大名单已全量完成。完整生涯填充仍在进行。

## 使用

打开索引和选手页面即可阅读。程序调用入口是 `kb.py`，只使用 Python 标准库：

```powershell
python knowledge/kpl/kb.py stats
python knowledge/kpl/kb.py validate
python knowledge/kpl/kb.py lookup 一诺
python knowledge/kpl/kb.py lookup Fly --at 2025-02-21
python knowledge/kpl/kb.py export
```

`stats` 的正式选手档案数与 `chronicle_import_candidates` 候选数分开显示；候选数不计入已确认的KPL选手总数。

`lookup` 返回带来源链接的 JSON，可作为 Codex 的背景输入。未找到或匹配多位选手时返回明确错误，身份不由程序猜测。

`--at` 是背景截止日期。它过滤后续经历；仅知道年份的事件采用保守规则，到该年结束才进入日期检索结果。身份信息单独提供，历史队伍以每条事件中的队伍字段为准。当前阵容、完整胜率、完整荣誉和首秀日期只在有对应证据时补充。

## 数据与证据

- `data/players.json`：唯一的选手、别名及事实来源。
- `data/sources.json`：原始出处、发布日、读取日及发布主体。`first_party` 是人工核查结果，不是程序自动认证。
- `data/coverage.json`：全历史目标、已知缺口和完整性标志。历史总人数尚未确认，因此不展示覆盖百分比。
- `profiles/`、`INDEX.md` 与 `TEAMS.md`：生成的阅读视图，修改原始 JSON 后重新导出。
- `data/coverage.json`：分别跟踪实际登场覆盖与大名单覆盖的缺口。
- `codex-context.md`：素材分析和人物叙事时的检索步骤。

每条事实都有稳定 ID 和来源。只有实际打开的一手来源（赛事官方、俱乐部官方或选手本人发布）可以把事实标成已核。用户编年史、百科和媒体材料可作候选线索或背景，但必须与确认事实分开，不能据此确认 KPL 正赛登场、身份或荣誉。官方微博在新浪等平台的原帖镜像需注明发布者和访问方式；媒体改写不视为第一方资料。原文标有“待核实”或出现来源冲突的内容必须保留疑点；没有证据的姓名、比分、日期、英雄、对手和身份关系留空，不用推算补齐。

事实以 `competition_type` 和 `competition_name` 标注赛事：`KPL_league` 表示 KPL 春、秋、夏等赛季联赛；`KPL_annual_finals` 表示 2024 年起的 KPL 年度总决赛；`KPL_cup` 表示挑战者杯、冬季冠军杯、冠军杯／世界冠军杯等 KPL 杯赛；`other_official_competition` 表示电竞世界杯、亚运会等其他官方赛事。每届赛事按官方正式名称归类，不能仅凭年份或文档简称推断；年度评选、周年纪念等非比赛事实不标成赛事，可使用 `event_name`。不能把杯赛、年度总决赛或其他赛事荣誉改写成 KPL 赛季联赛荣誉。

## 编年史内容组织标准

知识库及人物故事以用户提供的编年史结构作为组织参考：十年总览、逐年编年、十年热点事件、按位置的人物生涯、高光比赛索引。它们是同一组可追溯事实的不同阅读视图，不应复制成互相矛盾的独立事实。剪辑任务只取相关视图，不要求每条视频都复述整部编年史。

人物基础档案优先记录可核实的官方称呼与姓名、位置变化、按日期标注的队伍经历、KPL 首次登场证据和明确荣誉。没有一手来源确认本名时保留 ID，不以百科单独确认身份。队伍更名、席位收购、关联沿革逐项记录来源和生效时间；未证实的沿革只作待查映射，不据此合并身份或队伍记录。

高光记录尽量包含赛事正式名称与类别、比赛日期精度、阶段／对手／比分／小局、英雄、可见操作或官方赛后描述、结果或奖项及来源。只记录来源实际支持的字段；精确日期、局号、局内时钟、录像文件时间是不同精度，不相互推算。生涯榜单和统计必须保留原统计截止日期与适用范围。创作主题、人物评价和编排建议与事实分层；来源中的赞誉按发布者观点引用，心理活动、队内关系和因果判断不自行补写。

`lookup` 将核实记录和 `unverified_source_leads` 分开返回。未核线索仅供继续查证，不能作为选片叙事的事实依据。人物故事先由带日期、赛事类别和来源的事实时间线组成；主题与编排建议作为独立的创作建议附上事实 ID，旁白稿不默认生成。

### 什么能证明正赛登场

具体 KPL 联赛或年度总决赛赛后记录、明确的正赛首登公告、正赛中产生的个人比赛统计可作为证据。年度候选名单、注册名单和赛前首发公告提供身份与候选线索，须另补登场证明。挑战者杯、冬季冠军杯、冠军杯／世冠、其他杯赛或表演赛出场不能单独证明 KPL 联赛或年度总决赛正赛登场。

单次局内英雄记录只证明那场比赛使用过该英雄，不证明它是招牌英雄。官方榜单的当日或赛季排名保留原适用范围；不能转写成生涯排名。

### 扩充与全量验收

1. 按年度与赛事登记每届 KPL 联赛及年度总决赛，分别保留赛事类别，并核对比赛总场数、小局数和缺失记录。
2. 从比赛赛后名单、录像或正赛个人统计提取实际登场记录，再合并选手身份。
3. 改名、同名、位置变化与俱乐部更名各自补证，冲突保留待查状态。
4. 将首秀、转会、夺冠、FMVP、角色变化等经历逐条绑定来源和时间精度；史料不足的字段留空。
5. 每次增补运行 `validate` 和相关测试，更新覆盖缺口后导出。
6. 只有逐届比赛台账对齐、登场名单去重和全部缺口解决后，才确认全量完成。来源已打开与人工核查记录也要保留。

目前未实现自动采集或定时刷新，也未完成剪辑软件中的自动检索接线。此次构建提供本地知识数据、查询入口和接入说明。
