# KPL 素材分析：选手背景检索

分析KPL素材、判断选手身份或为选手经历拟定叙事时，先检索本知识库。数据库范围与缺口见 `INDEX.md`；按历史赛事队伍浏览 `TEAMS.md`。找俱乐部名单、转会或首发公告时，先查 `../../docs/kpl-team-official-weibo.md`，再引用具体原帖；账号主页只用于确认来源身份，不能代替事实原帖。逐条检索时区分实际登场事实与 `roster_listing`：后者只确认进入某类官方名单，不能证明选手完成了小局登场。该页不表示现役阵容。

## 处理步骤

1. 先把用户的自然语言要求解析成任务卡：集锦类型、选手/英雄/队伍主题、视频日期范围、长度、原声要求、可选字幕或慢放。将缺项标记为未指定，等待任务卡可编辑检查。
2. 从素材或任务卡提取比赛日期、赛事、战队、画面中的选手ID和解说提到的姓名。每项附素材时间点；未知项留空。
3. 用 `kb.py lookup <选手ID或姓名> --at <比赛日期>` 获取当时已有的背景。身份存在多个匹配时列出候选，结合画面与阵容核对后再选定。结果中的 `chronicle_source_leads` 来自用户提供的混合来源编年史，只是找原始资料的线索；未建档称呼也不代表身份或正赛登场已经成立。赛事先区分 KPL 赛季联赛、KPL 年度总决赛、KPL 杯赛和其他官方赛事；只有前两类的已核实际登场可计入目标正赛名录。
4. 对照队伍、对局、小局和英雄确认素材是否与史料事件一致。知识库记录的局内分钟是定位线索，须转换为实际素材时间；它不是本地录像剪切点。
5. 分别评价操作精彩程度和比赛意义。为每个候选片段输出素材起止点、画面证据、入选理由及使用的背景事实ID。两项分别可排序；不使用未确定的总分权重排除片段。
6. 将不确定片段保留为待审项，注明时间点、疑点及确认方法。先完成其余分析，再供用户集中审片。
7. 用户要求人物经历叙事时，再按明确的叙事截止日期检索全生涯背景。将录像当时的情况与后续经历分开，依事件日期和赛事类别组织事实时间线。
8. 只从 `verified_facts` 撰写事实。`unverified_source_leads` 与 `chronicle_source_leads` 都是待查线索，不能当作事实或用于确认选手身份、KPL 正赛登场和荣誉；需要时继续找联盟、俱乐部或选手本人一手来源。原文标注“待核实”或存在冲突的说法保留待核状态，不推算缺失的比分、日期、英雄、队伍和姓名。
9. 人物材料按编年史的组织标准从同一事实库生成：十年总览、逐年编年、十年热点事件、按位置的人物生涯、高光比赛索引。单次剪辑分析输出四个区块：已核事实时间线、素材观察、可选叙事主题、建议编排。史料引用事实 ID 和来源链接；观察引用素材时间点；叙事主题与编排标为创作建议并说明依赖的事实。旁白稿仅在用户另行要求时生成。

完成条件：自然语言已转成可编辑任务卡；候选片段都有素材时间、理由与两项评价；不确定项已保留并标记；人物叙事引用来源和事实ID；未知身份和时间留空。

## 叙事边界

先用首秀、位置变化、队伍变化、明确比赛事件和荣誉建立事实骨架。每条赛事经历保留准确的赛事类别和赛事名：KPL 赛季联赛用 `KPL_league`，2024 年起的年度总决赛用 `KPL_annual_finals`，挑战者杯、冬季冠军杯、冠军杯／世冠用 `KPL_cup`，电竞世界杯、亚运会等用 `other_official_competition`。类别不得相互挪用或合并成联赛荣誉。队伍沿革逐条附生效时间和一手来源，不因名称相似而自动合并。之后再讨论“初登场到代表作”“同英雄不同阶段”“操作改变比赛局势”等可选主题。

高光索引按比赛时间排序，保留来源实际给出的日期精度，并记录赛事／阶段、对手、比分、小局、英雄、操作、结果或奖项。比赛日期、局内时钟和本机素材时间码分别记录，不相互换算。生涯榜单记录统计截止日；单局出场不推断招牌英雄或长期风格。

官方回顾中的赞美与情绪表达作为出处观点处理。未经本人或可核实采访证明的心理活动、队内关系和伤病原因，不写成传记事实。昵称、粉丝绰号、英雄熟练度及当前战队均要有各自的证据。

知识库用于检索背景。身份和操作的最终判断要匹配当前素材；没有收录到的选手继续标记待查，不强行匹配知名选手。
