# KPL 历史实际登场选手：第一方来源调查

- 调查日期：2026-10-03 至 2026-10-04（Asia/Shanghai）
- 目标时间范围：2016 年首届 KPL 至 2026-10-04 已发生的比赛。
- 用户确认范围：所有历史上在 KPL 正赛实际登场的选手。
- 当前状态：已验证部分官方来源与取证路径；**尚未完成历届枚举，也没有证明名单全量完整**。

## 本轮结论

不能把某赛季大名单的所有人自动加入“已登场选手”集合。应先记录注册名单作为候选，再通过比赛完成后的逐局数据、官方战报或原始录像确认实际登场。赛前首发公告比注册名单更接近实际阵容，但仍然只证明当时公布的安排；替换、改期和局间轮换需要另行核对。

本轮找到可读取正文的 KPL 联盟及俱乐部官方微博、腾讯赛事入口，以及官方 B 站账号的 2016 赛事录像索引。没有发现并验证一个可直接下载、涵盖 2016 至今全部实际登场选手的官方开放数据库，也没有验证稳定、公开文档化的官方 API。

## 当前数据库样本（不是全量覆盖）

截至 2026-10-04，知识库有 67 个选手条目，其中 65 个有已核 KPL 正赛登场证据、2 个待补一手来源（晨风、小乐）；208 条事实中 205 条已核、3 条待核，来源共 35 条。历史总人数和各赛季实际登场人数仍未知；这些数字不得解释成名录完成比例。当前仍缺逐届赛事清单、逐场出场台账和选手身份去重，`coverage.json` 的全量完成标志继续为 `false`。

## 从赛季到全量选手的可靠枚举流程（建议实施，未完成）

1. **先建赛事清单**：逐年记录 KPL 春季、秋季或夏季及适用的 KPL 年度总决赛，核对正赛阶段、赛程、参赛队伍。资格赛、K 甲、青训、表演赛、冠军杯／世冠等保留独立赛事类型；杯赛可以补人物经历，但不能单独用于证明“KPL 正赛登场”。
2. **获取赛季注册候选**：由联盟注册公告、官方战队页面或俱乐部公告录入，状态为 `registered_only`。姓名、ID 变更、队名历史按有效时间保存，未知项保持未知。
3. **按已完成大场和小局遍历**：优先逐局官方数据，其次官方赛后战报和原始录像；记录赛事、日期、双方、局号、十个实际场内 ID、身份映射依据及来源位置。赛前首发暂记 `announced_starting`。
4. **确认身份后升级状态**：至少一条 KPL 正赛已完成小局的直接出场证据，才能记 `confirmed_appearance`。赛季官方“登场局数 > 0”如能明确赛事范围，可证明赛季曾登场，但不能自行推出具体首秀日期。
5. **做覆盖核算**：每赛季记录预期大场数、已处理大场数、逐局缺口、身份待合并数和来源失效数。不能用“已收若干热门选手”代替覆盖率；不宣称完整直到赛事清单和逐场覆盖经过复核。
6. **另建经历事实**：转会、位置变动、荣誉、纪录、伤停等单独带时间与来源；剪辑故事由事实派生，区分事实和叙事建议，避免把“曾获候选资格”写成获奖，把如今队伍带入旧录像。

上述步骤是对已观察到的名册、首发和录像来源差异作出的工程方案，不是官方公布的采集规范。

## 公开数据库与获取难点

- [KPL 当前战队入口](https://kpl.qq.com/#/Teams) 和 [腾讯历史数据入口](https://datamore.qq.com/project/wzmatch/dist/index.html#/) 本轮直接抓取均出错。只能保留为待验证入口，不能声称读取到其数据库、字段或历年完整内容。
- 腾讯赛事中心主要依赖动态页面／iframe，静态提取不足以取得实际数据。下一步应在可用浏览器会话里查看公开页面并记录真实响应与字段，再决定做受控适配器还是人工导入；本轮没有虚构接口地址或稳定性承诺。
- 官方微博图片名册需 OCR 和人工核对；文本与图片可能已编辑。要保存发布日期、获取时间、原链接和证据片段，保留编辑或失效状态。
- 早期团队解散、改名、ID 罗马字／中文变体会增加查找和去重难度。不要只凭相同 ID 或中文昵称合并两个人，也不要只凭队名不同把同一人拆成多个人。
- 搜索中出现的 Liquipedia、Wikipedia、ModelScope 用户数据集、小元电竞和转载新闻可用作索引线索，**不是本报告认证的第一方登场证据**。数据集“来源官网”的自述不足以证明数据内容、更新日期、覆盖或实际出场语义。
- 多个以“KPL 官网”自称、但不属于腾讯域名或可核实官方账号的网站出现在搜索结果中。本轮未把这些网站视为官方来源。
